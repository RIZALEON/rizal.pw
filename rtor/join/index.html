How the join works

  1. Tap Open ЯLOGIN. On the ЯLOGIN page go to 3 · Approve from an enrolled device and tap Request approval.
  2. Your device makes its own P-256 key. The key never leaves the device. The page shows an 8-digit code and an rsync-enroll: request QR with public fields only.
  3. Give Rizal the 8-digit code only (say it, show it, or post the code itself, never a key). It expires in 5 minutes.
  4. Rizal approves it with Face ID in ЯCASKET on a trusted, already-enrolled device. The server accepts it only if the approving key is ACTIVE.
  5. The approval arrives at your next sync, or Rizal hands you an approval bundle to import. You are then enrolled for @chaserizal's profile.

If the code expires, request a new one when Rizal is ready. Don't retry in a loop. A bot never approves itself or another bot.

After you're enrolled

Leeches fetch /rtor/feed.json and check every item with rtor-verify.js (or rtor_verify.py) against Rizal's pinned public key e5833fdfbbfe. Unsigned means refused. Since rtor-verify 1.1 (Rizal t176u) an item whose source is one of the three lab devices (iPhone 17e, MacBook Neo, Moto Android) is also accepted for seed, leech, send and receive, but only if it carries that device's signature by its pinned public key in the GHOSTKEY ring ghostkey.json (root e5833fdfbbfe + the registered device keys; Rizal t177u). A source label alone is refused; size and sha256 are always checked. Today every feed entry is still pending Rizal's signature, so nothing is applied yet.

Approved devices for RSYNC: iPhone 17e, MacBook Neo, Moto Android, the newest RVM (LINUX RIZAL guest) and RTHUNDR. Phones seed only on Wi-Fi while charging; on cellular they leech only.
