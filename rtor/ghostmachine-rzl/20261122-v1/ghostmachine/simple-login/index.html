Sign in

Method: site vault → Ed25519 signature checked against the pinned site key → your entry is opened with PBKDF2-SHA256 (600k) + AES-GCM. A wrong password simply fails to decrypt — there is no record to fall back to. 5 wrong passwords lock that handle for 60 seconds — and signing out does not reset the lock; it expires on its own timer.

Signing capability comparison

Signing iOS apps without a Mac — what each tool actually does today. Facts checked 2026-11-21 against each project's own repo and docs.

ToolHost OSIntegrated signingSigning target / notes
xcrossLinux, WindowsYes — Apple ID (free) or App Store Connect key; in-process signing; offline after initial setupFlutter & Compose apps on a physical iPhone, iOS 17+. README claims debug JIT plus profile/release AOT device apps, but its site notes release still needs a Mac. Apple may lock the Apple ID used — use a spare. Repo: arxdeus/xcross.
xtoolLinux, Windows (via WSL), macOSYes — Apple Developer Services; Apple ID password or ASC API keyBuilds SwiftPM apps and signs + installs on a USB iPhone in one xtool dev. Needs Swift 6.4 + Xcode.xip for the SDK. Free-ID sideloads expire after 7 days. Sign-in broke repeatedly in Oct 2026 with 2FA issues on 1.24.0. ~14k stars, MIT. Repo: xtool-org/xtool.
CrossCodeLinux, WindowsSigning moved out — sign via the standalone isideload packageAlpha Tauri + React IDE. Swift 6.2 + SPM; Darwin SDK comes from a user-provided Xcode 26. Its signing code was moved out of the IDE into isideload, so signing is done through that package, not in CrossCode itself. Repo: nab138/CrossCode.
zsignLinux, Windows, macOS, Android, FreeBSDSigning engine, CLI — re-signs only, with an existing cert + provisioning profileC++ CLI for iOS IPA / app re-signing: zsign -k key.pem -m dev.prov -o out.ipa app.ipa. It does no provisioning of its own — you bring the certificate and profile. ~2k stars. Repo: zhlynn/zsign.
isimLinuxNo — simulator + toolchain onlyiOS development (simulator). Its own status table says device build / signing / .ipa is BLOCKED, and there is no TestFlight from Linux. Repo: kolabs-dev/isim.

Also in the field

  • ipeddle — Linux; builds an unsigned IPA, no signing at all — sign afterwards via Sideloadly or AltStore.
  • isign — old Python re-signer, last release 2016; needs credentials exported from a Mac.

Best choices

  1. xcross — best automated iOS signing from Linux/Windows. Signing using an Apple ID or App Store Connect credentials, provisioning, installing on physical iPhones, and offline signing after the initial setup.
  2. xtool — best general Swift/iOS development workflow. Integrated Apple Developer Services, builds, signing, device installation, and certificate-based workflows across host operating systems.
  3. zsign — best standalone signing engine. Slots into automated pipelines for re-signing iOS packages across multiple operating systems.

GHOSTSIGN / RKCRYPT PROPOSAL — NOT BUILT

One system signing releases for Windows, Linux, macOS, Android and iOS is a different architecture from any single tool above: a universal signing pipeline with a platform-specific signing backend behind each target, rather than Xcode alternatives alone.

For GHOSTMACHINE, that would be a unified GHOSTSIGN / RKCRYPT signing service integrated with RTOR, GitHub, the build bots, and device deployment. This is a proposal only — no such service exists yet.
