how this works: the first bind registers a key on the device; on later visits the device proves itself by signing a fresh challenge. The private key never leaves the device — only the public key is kept.

the key is bound to this site's address — a key registered here works here; on another site (for example rizal.info) the device must be registered again there.

there is no server in this check — the public key lives in this browser next to the record and verification runs locally, so this recognises the device; it does not replace the password sign-in.

a brand-new device still needs its one first bind (picker or register) — no system can identify a device it has never seen.
